# Changelog

All notable changes to `reactor-effect-client`, `reactor-effect-browser` and `reactor-effect-native` are documented in this file. The three packages are always released together, with one version.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

The next release is 0.3.0, because `main` already breaks the 0.2.0 API. A `^0.2.0` range does not include 0.3.0, so applications move to it deliberately.

Qualification: on September 23, 2026 the ABI 3 media path passed `native:test` in a linux-x64 container (Rust 1.90.0, Clang 21.1.8, Node 24.15.0, Bun 1.4.2) and in CI on GitHub's linux-x64 and darwin-arm64 runners on Node and Bun, with the Chrome integration test on each; the README's support section keeps its measured limits, and the full record is in the README at [c2e6618]. Against the ABI 2 bridge, the same load tests had failed throughput, stall and renewal on Bun and the two-session test on Node. Getting them to pass on the darwin-arm64 runner took linking the far peer against compiler-rt, holding its congestion controller at a fixed rate and stopping Spotlight during the native job.

### Added

- `EngineShape.observe(options)` and `Source.observe(options)` return an `EngineObservation`: the engine's state and a stream of every event after it, subscribed before the state is read, so no event falls between them. Events may repeat what the state already reflects and are applied by `clipId`; after an `Overflow`, observe again. `Observations.observeWith(state, options)` builds the same pairing for a host's own observations.
- `recorder(stream)` turns one track's frames into every frame it delivers plus a `Lost { after, count }` element wherever the host dropped frames between two it delivered, from their admission sequences; `Recorded` is its element type. A preview keeps using `Stream.buffer({ capacity: 1, strategy: "sliding" })`.
- `provider.operation(submission)` returns a committed submission's `ClipOperation` for as long as its scope holds it: `accepted`, `reached("generated" | "started")`, `ended` and `facts`, each resolved once from the provider's own reducer. A phase completes when it or a later one is observed, from a lifecycle message or a queue or state snapshot, and every `ClipFact` names the transport generation of its evidence; a clip that fails or is popped first fails the phases it never reached with the new `ClipEnded` reason; a definite enqueue failure fails every fact with that failure; and a provider that retires first resolves the rest as `Indeterminate`, a new failure code. A clip carrying the submission's metadata still resolves an unknown enqueue after its reconcile window or in a later transport generation of the same session, without changing `provider.acceptances`. A commit takes one of `maxOperations` slots (1024 by default) before it sends: ended operations are evicted first, and a table of unresolved ones refuses the commit with `Overflow`, not submitted. Releasing the scope acknowledges the operation and frees its slot.
- `Orchestration.openH3({ mint, onAllocated?, create?, source? })` opens a paid H3 session as an orchestration source: it mints the session token (the API key never reaches it), allocates the session with `Client`, runs `onAllocated({ session, grant })` before connecting so the application can record the owner durably (the grant's `jwt` stays `Redacted`), connects, and derives the source with `fromH3Session`. It returns `{ source, lifetime }` with the granted session length as a lifetime in seconds, so it is directly a renewal `open`. A failure after allocation closes the session first and reports its cleanup in an `AcquisitionFailure`; an application error from `onAllocated` is returned as it was.
- Schemas for the evidence the client returns, so an application can persist it without redefining its shape: `CloseReport` and `Termination` at the root (also `Coordinator.Termination`), and `Orchestration.CleanupReport`, `SourceCleanup` and `PolicyCleanup`. Each is also its type. Encode to JSON with `Schema.toCodecJson`. A failure inside a report encodes as its diagnostic JSON (`toJSON`), so provider text (`body`), native backend text and `context.detail` never reach the stored form, and decodes back to a failure of the same class without them.
- `Orchestration.Allocation`, a durable owner record `{ sessionId, ownership, model, expiresAt }` without the token, and the `allocation` field of `openH3`'s `onAllocated` argument, which carries it.
- Orchestration options `maxQueuedVideoFrames` and `maxQueuedAudioSamples` set how much undrained media the output keeps before it fails with `Overflow`, 96 frames and 192,000 samples (4 seconds each) by default, as before.
- `Orchestration.layer(options)` provides the `Engine`, `Media` and `Handle` services of one orchestration, as `Simulation.layerSim` does for a simulated one, so the three can never come from two paid session chains.
- `HandleShape.observe(options)` returns the handle's engine and media state with one ordered stream of `HandleEvent`s after it: engine events, `Renewal` events and `MediaState` transitions, in the order they happened, so a `Replaced` follows the `Failed` events of the clips it lost and a media state never arrives out of order. It subscribes before it reads, like `engine.observe`, which is now its projection.
- A span for each operation a caller can cancel: `reactor.session.create` and `attach` (with the model name or attached session id), `reactor.session.connect` and `reconnect` (with the connection generation, session id and an event per phase: `reactor.connect.described`, `prepared`, `registered`, `offered`, `answered`, `ready`), `reactor.session.upload` (MIME type and size only), `reactor.session.close`, and `reactor.orchestration.renewal.open`, `recover`, `replace` and `switch`. An H3 enqueue runs in a `reactor.h3.enqueue` span on the submission's own execution, with its acceptance wait in `reactor.h3.reconcile`. `reactor.coordinator.terminate` and `reactor.session.close` carry the termination verdict as `reactor.termination.attempted`, `confirmed` and `evidence`, because termination reports rather than fails and its span otherwise ends without error even when a paid session was not confirmed stopped. Every span skips stack capture, and none records a credential, input, reply or provider text; the renewal tick, frames and heartbeats are not traced.
- Each dispatched model command and control request runs in a `reactor.session.command` or `reactor.session.control` client span on the session-owned execution. The span is a child of the caller's span and ends with the request's own outcome, even after the caller stopped waiting. It carries `reactor.operation`, `reactor.request.id` and `reactor.connection.generation`, and on exit `reactor.command.outcome` and, for a typed failure, `error.type` set to its reason's tag. It never carries the input, the reply or provider text. A request refused before dispatch opens no span, and heartbeats are not traced.
- The client's failures route on a tagged `reason` with `Effect.catchReason`, `catchReasons` and `unwrapReason`. The reason classes are exported: `Failure`, whose tag is a code such as `Timeout`; `Http` (`status`, `retryAfter`, `body`); `Remote`, tagged `Remote` or `RecorderDisabled` (`remoteCode`, `body`); `Native` (`status`, a Redacted `backendMessage`); `IceFailed` (`pairs`, `candidateTypes`); and `TransportFailed` (`pairs`). `ReactorError.fromCode(code, message, context?)` builds the reason a code names. From `/orchestration`, `PolicyFailure` reasons are `Refusal`, `Missing` and `SequenceRefusal`.
- `isReactorFailure` recognizes any of the four failure classes, and `ReactorError.is`, `CommandFailure.is`, `AcquisitionFailure.is` and `PolicyFailure.is` each recognize their own class. `ReactorFailure` names their union.
- Every failure class has `isRetryable` and `retryAfter`, following Effect's `AiError`. `isRetryable` is true for the not-submitted `Overflow` of a pending-request bound, a connection lost before dispatch (`Disconnected`, `ChannelClosed`), an `Http` failure with no response or a 408, 429 or 503 or a `Retry-After`, and the `QueueFull` and `SessionRecovering` refusals. It is never true when `context.outcome` is `"unknown"`. `retryAfter` is the `Http` reason's `Duration`.
- `/orchestration` exports `EngineError = CommandFailure | PolicyFailure`, the failure of every engine command. Both carry `context.outcome`, so a classifier reads it without narrowing.
- `reactor-effect-native`: `NativeOptions.shutdownTimeout`, a `Duration.Input` that defaults to 10 seconds, bounds how long closing a connection waits for the native owner join. A value that is not a positive duration fails with `InvalidInput` when the layer is built; `"Infinity"` restores the unbounded wait.

- The root exports the Schemas of the session descriptor and its parts, `SessionDescriptor`, `Capabilities`, `Track` and `Mapping`, and derives the `Descriptor`, `Capabilities`, `Track` and `Mapping` types from them. A field the provider sends as `null` or omits decodes as absent; `Descriptor.raw` still keeps what it sent.

### Changed

- **Breaking** for implementations of `EngineShape` or orchestration `Source`: both must provide `observe`. An orchestration now subscribes to each source's events when it registers the source, before anything else runs, instead of when its reader first runs, so no source event emitted in between is lost to the handoff's frame accounting.
- **Breaking:** every `VideoFrame` declares its pixel layout in `format: VideoFormat` (`"BGRA"` or `"RGBA"`); the native host produces `"BGRA"`, and a `RawMedia` implementation (or a simulation renderer) must set it. `MediaPressure` gains `readerOverflows`, the readers of a generation's tracks that fell behind their bound and failed with `Overflow`, so one snapshot covers every loss point; `RawMedia` implementations must report it.
- **Breaking:** an orchestration's `media.video` and `media.audio` admit one reader at a time: a second concurrent reader fails with `AlreadyReading` instead of silently splitting frames with the first. A reader that ends releases the output, and a later reader resumes from what is retained.
- An orchestration's `media.pressure` reports the loss of its logical output: `droppedVideo`, `droppedAudio` and `readerOverflows` now accumulate across source replacements, counting each source only while it fed the output, instead of restarting from the new source's counters. Mandatory consumption and the terminal `Overflow` of an undrained output are documented.
- **Breaking:** downloading a prepared recording is part of the portable client: `Coordinator.Client.downloadClip(clip, options)`, with `Coordinator.parsePlaylist` and the `Segment`, `DownloadOptions` and `DownloadedClip` types. `Browser.Recording.downloadClip` now takes the public `Coordinator.Client` from `Coordinator.make()` instead of the `/host` `CoordinatorClient`, so no application API needs `/host`. **Breaking (`/host` only):** `/host` no longer exports `CoordinatorClient` or `retryAfterMs`.
- **Breaking:** `orchestration.fromH3(session, provider, { media, ...policy })` is replaced by `orchestration.fromH3Session(session, { provider?, ...policy })`. The new constructor builds the session's H3 provider view and its decoded media itself, so a source can no longer pair one session's commands with another session's media, and returns them as an `H3Source` whose `provider` field exposes the provider's own operations. It needs a connected session on a host with decoded media, and otherwise fails with the session's own error (`UnsupportedCapability` on a host without decoded media) before any provider observation or policy command. `H3SourceOptions` is replaced by `SessionSourceOptions`.
- **Breaking:** a host is selected and validated when its layer is built. `Native.layer(options)` and `Browser.layer` are `Layer<PeerFactory, ReactorError>`: building the native layer loads Koffi and the library and verifies the staged artifact once, and building the browser layer detects WebRTC, so an unsupported host or an invalid native option fails there, before any `Client` exists to allocate a remote session. `Native.make` and `Browser.make` are removed, because `Effect.provide` would release the host layer when the factory effect ended; compose `Reactor.layer(configuration).pipe(Layer.provide(Native.layer(options)))` instead. `PeerFactoryShape.check` is optional and stateless: `make` no longer depends on it having run, and the session factory still runs it, when present, before every remote allocation.
- **Breaking:** `ReactorError`, `CommandFailure`, `AcquisitionFailure` and the orchestration `PolicyFailure` are independent `Schema.TaggedError` classes built from their fields, each with its own `_tag`, instead of `.extend` subclasses that shared `_tag: "ReactorError"`. `catchTag("PolicyFailure")` now compiles and `catchTag("ReactorError")` no longer catches the other three, none of which is an `instanceof ReactorError`; use `isReactorFailure` or a class's `is`. The positional `new ReactorError(code, message, context)` constructor is gone. `CommandFailure.from(error, context)`, `AcquisitionFailure.from(error, cleanup)` and `PolicyFailure.refuse(code, message, operation?, cause?)` build the derived forms, and `PolicyFailure.missing(purpose)` and `PolicyFailure.sequence(id, code)` the other refusals ([3f48e19]).
- **Breaking:** a failure's category moves from a flat `code` to its tagged `reason`, and there is no `code` alias: read `reason._tag`, whose values are the former codes and which `ErrorCode` still lists. `message` is the reason's message. `ErrorContext` keeps the operation, request, session, generation, outcome and the inspection-only `detail`; its `status`, `retryAfterMs`, `remoteCode` and `body` move into the `Http` and `Remote` reasons, and `retryAfterMs` becomes the `Duration` `retryAfter`. A 426 or 501 is still `VersionMismatch`, whose status and body are in `context.detail`. Diagnostic JSON now reads `{ _tag, message, reason, context }`.
- **Breaking:** `PolicyFailure.reason` is a closed union instead of an open string: a `Refusal` tagged `QueueFull`, `SessionRecovering`, `SessionClosed`, `SessionRetired`, `NotFound`, `OwnerConflict`, `Busy`, `InvalidRequest`, `PositionConflict`, `QueueChanged`, `RouteChanged`, `AnchorUnavailable`, `ContinuationUnavailable`, `AnnotationCapacity`, `SubmissionCapacity` or `IdentityExhausted`; `Missing`, whose `purpose` names the request field (the former `*_missing` strings); or `Sequence`, carrying the sequence's id and `SequenceError` code (the former `sequence_*` strings). Its `context` is `{ operation, outcome: "not-submitted" }`, with the outcome typed as that literal.
- **Breaking:** the root no longer exports `ProviderFailure`, and `ReactorError` loses the `nativeError` field, which nothing set; the typed reasons carry those fields. `ErrorContext` is exported as a type only.
- **Breaking:** signatures name what each operation raises. `EngineShape` and `Source` commands fail with `EngineError`, which replaces the `CommandError` and `EnqueueError` aliases. Orchestration and simulation `make`, `layerSim` and `Options.open` fail with `ReactorError | AcquisitionFailure`, and an `AcquisitionFailure` from `open` fails `make` unchanged. `fromH3` fails with `ReactorError | PolicyFailure | CommandFailure`, H3 `make`, `prepare` and `prepareFrom` with `ReactorError | CommandFailure`, and `Source.reconnect` with `ReactorError | CommandFailure`. The orchestration's terminal failure (`failure`, `SessionFailed`, `MediaState` and the orchestrated media streams) is the `ReactorFailure` it was raised as, so a replacement's `AcquisitionFailure` keeps its cleanup.
- **Breaking:** H3 prepare hooks and preparations may refuse with a `PolicyFailure`, which fails the submission unchanged instead of becoming a `CommandFailure` without its reason.
- **Breaking:** `Sequences.SequenceError` and `InvalidSequenceOptions` are `Schema.TaggedError` classes. `SequenceError.reason` is now `code`, listed by the exported `SequenceCode`, and `InvalidSequenceOptions.reason` is now `message`.
- **Breaking:** invalid `session.command` input (its name, data, uploads or deadline) fails as `InvalidInput`, not `Protocol`; it is still not submitted and sends nothing. A parser's rejection stays a typed failure while a bug in a parser, check or reducer stays a defect, instead of every throw becoming a typed `Protocol`.
- **Breaking (`/host` only):** `errorOf(cause, code, operation?)` requires its code and serves platform exceptions only; `parse` and `parsed` run a parser that rejects with a `ReactorError`, and let anything else it throws stay a defect.
- **Breaking:** every time option is an Effect `Duration.Input` named by its role, and a bare number is milliseconds, as everywhere in Effect, so a seconds value needs its unit: `leadSeconds: 30` becomes `lead: "30 seconds"`, because `lead: 30` is 30 milliseconds. NaN, which `Duration` decodes as zero, a negative value and a value past the option's maximum fail with `InvalidInput`, not submitted. `"Infinity"` disables the heartbeat, replacing `heartbeatMs: 0`, and marks a source that never expires. Each removed key stays declared as `?: never` through 0.3.0, so a configuration that still sets one, held or spread, fails to compile; the declarations go in the next minor. Measurements, instants and media lengths stay numbers: `requestRecordingClip(seconds)`, `ClipRequest.durationSeconds`, `ageSeconds`. `/host` exports the shared normalizer, `duration(input, name, policy)`.

- **Breaking:** `Session.command(name, data, options?)` and `Session.upload(name, mimeType, bytes, options?)` take an options object in place of their trailing positional arguments: `{ uploads?, replyTimeout? }` and `{ uploadTimeout? }`. Each override shares its key with the session's default, which it replaces for that call. `replyTimeout` is the session's own reply deadline: after dispatch it fails with `Timeout`, outcome `unknown` and the command's `requestId`, and the slot stays held until a late reply or the generation retires. To stop waiting without that, fork the command and bound `Fiber.join` with `Effect.timeout`. `reactor-effect-browser`'s `play(track, element, { playTimeout? })` does the same for its deadline. The compiler rejects every old call: a fourth argument is an arity error, and a bare uploads map or a number has no property in common with the options.
- H3 bounds each reference upload by its own `uploadTimeout`, 60 seconds by default, instead of its 15-second command budget.
- Coordinator replies (a session descriptor, a create reply's session id, ICE servers, a connection registration, an SDP answer, an upload allocation and a key exchange) are decoded by Schema after the bounded JSON copy, and the H3 `state_update` and `queue_update` cross-field rules are Schema filters. A malformed reply fails `Protocol` as before, with a message the library writes (`invalid session descriptor`, `H3 queue_update payload is malformed`) in place of the per-field one, and keeps the `SchemaError` in `context.detail`, which names the failing path but no input value. `reactor-effect-native` decodes a prepared mapping with the client's `Mapping` schema, so it also rejects an empty track name.
- **Breaking (`/host` only):** `/host` no longer exports `isRecord`, which `Predicate.isObject` replaces, or `readFileBytes`, which no host used; `uploadFile` still reads a file for an upload. It adds the time normalizer `duration`.
- An orchestration's `onRenewal` runs on a reader the handle forks, in order, instead of inline under the handle's command permit, so a slow renewal observer no longer delays `enqueue`, `setAutoplay` or any other command. Its failures are logged and do not stop later events; close waits up to one second for it to finish what was announced.
- **Breaking:** the orchestration `log` option is removed. The orchestration logs through Effect's logger at debug level, annotated with `module: "reactor.orchestration"`, so the application's logger and level decide what is kept. `log` stays declared as `?: never` through 0.3.0.
- **Breaking:** every `VideoFrame` and `AudioFrame` carries `sequence`, its admission number on its track in its generation, from 0, taken before any bounded queue could drop it, so a gap between two frames a reader receives is the count the host dropped there. A `RawMedia` implementation, or a simulation renderer, must set it.
- **Breaking:** `reactor-effect-native` loads only an ABI 4 native library: its frame and PCM headers carry the admission sequence (48 and 24 bytes), and an ABI 3 library, including one built from an earlier `main`, is rejected at layer build.
- **Breaking:** `ErrorCode` gains `ClipEnded` and `Indeterminate`, so an exhaustive match over the reason tags must handle them.
- **Breaking:** zero-argument operations are `Effect` values rather than functions returning one: `Coordinator.Client.pricing`, and `Peer.stats` and `Peer.shutdown` in the host peer contract (`Peers.Peer`). A custom `Peer` exposes `stats`, and `shutdown` when it has one, as values ([6291dc5]).
- **Breaking:** `ClipRequest`'s `durationSeconds`, `seed` and `position`, and `Coordinator.Inspection`'s `observedAt` and `additional` values are `Schema.Finite`, so NaN and infinities neither decode nor construct ([6291dc5]).
- **Breaking:** `reactor-effect-native` loads only an ABI 3 native library and rejects an ABI 2 library, including the 0.2.0 one passed as `libraryPath`. Decoded media now reaches JavaScript through bounded native queues drained with nonblocking takes, off the libuv thread pool, and every peer in a process shares one libwebrtc factory ([90f3b05]).
- **Breaking:** `ErrorCode` gains `SdpRejected`, `IceFailed`, `TransportFailed` and `ChannelClosed`, so an exhaustive match over the reason tags must handle them. A data channel that closes now fails the connection as `ChannelClosed` rather than `Disconnected`, and a failed native connection reports `IceFailed` or `TransportFailed` from its statistics ([90f3b05]).
- **Breaking (`/host` only):** `CoordinatorClient.create` resolves with the allocated session id and the reply, and the new `describe` decodes the session descriptor from it. `/host` serves the first-party host packages, which pin the exact client version.
- The three `ReactorError` messages that repeated provider text now carry a message written by the library: a data or control command's `Remote` error reads `remote command error <code>`, and a failed clip request reads `clip failed`. The provider's text moves to the `Remote` reason's `body`, which diagnostic serialization excludes, so code that read it from `message` reads `reason.body`, and routes on `reason._tag` and `reason.remoteCode`. A disabled recorder is still reported as `RecorderDisabled`, recognized from the clip failure's text; it is the one documented exception to never classifying provider text, until the wire carries a code for it.
- Each failure's native `cause` is its reason, as for Effect's `AiError`, and a reason holds no raw cause: a response body, a wire message, native backend text or a JSON `SyntaxError` quoting its input stays in `context.detail`, a `body` field or a Redacted field, so neither `Cause.pretty` nor an `OtlpTracer` export renders it. libwebrtc's text, which can contain peer SDP, is Redacted, and an HTTP body or a native backend message is also left out of a reason serialized on its own.
- `reactor-effect-browser`: a `play()` timeout's message reads `media play deadline` instead of `media read/copy/play deadline`; its reason is still `Timeout`.
- `reactor-effect-native`: while a timed-out owner join is still retained, preflight (`PeerFactory.check`) and peer creation for that library fail with a `Native` error that was not submitted, before any allocation, instead of starting another owner on a libwebrtc factory that may be wedged. The library admits peers again once the join completes.
- `VideoFrame` and `AudioFrame` document that every subscriber to a track receives the same frame object and buffers, so readers treat them as read-only and copy before writing. This was already the behavior.
- `reactor-effect-native`: the Rust library no longer panics outside tests, where a panic in a libwebrtc callback would abort the host process, and checks every pointer's alignment and length bound before touching caller memory ([efd9e51]).

### Fixed

- `provider.observe` no longer delivers an event its `initial` snapshot already reflects. A scheduler yield between the subscription and the snapshot read let the reducer apply a queued event that then appeared in both; events at or below `revision` are now dropped, as `session.observe` drops them, except acceptances, which no snapshot holds, and diagnostics without a source.
- A create reply that names its session but fails validation later, for example with an unknown track kind or malformed capabilities, no longer orphans the paid session. The session is recorded as owned from its id, the acquisition fails with a `Protocol` `AcquisitionFailure` whose `context.sessionId` names it, and cleanup deletes the session and confirms its termination (`cleanup.allocation` is `"known"`).
- JSON validation of caller input (command data, `extraArgs`, orchestration clip requests, H3 command data and `/wire`'s `structFromObject`) enforces its documented bounds. Object keys count toward the 4 MiB text budget; array holes and index accessors are rejected, and an accessor never runs; an array's length is charged against the node budget before any slot is read, so a sparse array with 100 million slots fails in milliseconds instead of passing after seconds. Each violation is still a typed failure that was not submitted. An array's non-index own keys are ignored, as `JSON.stringify` ignores them.
- A renewal `open` that returns a source whose `lifetime` is no longer than the renewal `lead` fails with `InvalidInput` instead of preparing a replacement immediately after every open, bounded only by `maxSessions`.
- Closing a media stream waits at most one second for the host's `ReadableStream` cancel before releasing its lock, so a cancel that never settles no longer holds the finalizer that runs ahead of paid-session termination.
- Checking an H3 provider's retained-byte bound no longer walks everything the provider retains on each event: a running total counts each retained object once, from when its first holder takes it until its last drops it. The bound is unchanged in meaning and may trip slightly earlier, because an object held by two retained entries counts twice.
- A minted token whose returned grant is refused keeps why in the failure's inspection-only `context.detail`, as other rejected replies do.
- An H3 refusal (`command_error`) keeps the provider's reason in its `Remote` reason's `body` instead of dropping it.
- `reactor-effect-browser`: the deadlines for resuming and closing the `AudioContext` in `audioContext()` and for starting playback in `play()` run on Effect's `Clock` instead of a wall-clock `setTimeout`, so `TestClock` controls them. Under the live clock they behave as before.
- `reactor-effect-native`: a native owner join that never completes no longer blocks `Session.close` and leaves the paid session running. At the `shutdownTimeout` deadline the close stops waiting, `CloseReport.localErrors` records a `Shutdown` failure ("native owner join exceeded its deadline; handle retained") and `localClosed` is false, and cleanup still terminates the remote session. The join keeps the native handle and its Koffi callback, and destroys and unregisters them only when it completes.
- A caller's JWT that the platform rejects as an HTTP header value fails as `InvalidInput` without keeping the platform's message, which quotes the value.
- `reactor-effect-native`: classifying a failed connection as `IceFailed`, `TransportFailed` or `Disconnected` runs in the events pump under a 2 second deadline on Effect's `Clock`, instead of an unowned wall-clock `setTimeout`, so `TestClock` controls it and closing the connection stops it. Its outcomes are unchanged.

## [0.2.0] - 2026-09-23

Qualification: on September 22, 2026, before the canonical API migration and the workspace split, the ABI 2 bridge passed its Rust tests (including the real libwebrtc loopback), clippy with warnings denied and its JavaScript native tests on macOS arm64, and again in Linux x64 userspace under Rosetta translation, with glibc 2.36 on Node 24.14.1 and Bun 1.4.2. That Linux run found that Clang 14 cannot compile the pinned WebRTC headers, so the build recipes select Clang 21. Chrome 153 exchanged binary messages and media with the native bridge, directly and through a loopback-only Coturn 4.18.0 relay. No hosted Reactor generation was run. The full records are in the README at [eb0db13].

### Added

- First publication of the three packages, built from commit [eb0db13] and published to npm with SLSA provenance by the release workflow.
- `reactor-effect-client`: the canonical `Client` and scoped `Session` (allocation or attachment, commands, connection generations and cleanup evidence in `CloseReport`), coordinator operations (pricing, token minting, inspection, termination), the H3 provider (`/h3`), orchestration and renewal (`/orchestration`), an offline simulation (`/simulation`), test utilities (`/testing`), the generated wire codec (`/wire`) and the `/host` surface for host packages. It runs on Node 22 or newer, Bun and browsers, with Effect `4.0.0-rc.115`.
- `reactor-effect-browser`: an `RTCPeerConnection` host with generation-scoped tracks, media conversion and recording.
- `reactor-effect-native`: a libwebrtc bridge in Rust, loaded through Koffi (native ABI 2), with decoded media, file upload and staged libraries for linux-x64 and darwin-arm64, on Node and Bun.
