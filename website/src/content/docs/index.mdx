## What it does

<CardGrid>
  <Card title="Stay on air" icon="rocket">
    `Playout` keeps H3 playing across capped sessions. It opens the next session before the current
    one ends and switches at a clip boundary. On hosted H3, clip-to-clip seams measured 46–169 ms
    with no dark frame, and a planned switch between sessions 420–432 ms.
  </Card>
  <Card title="Frames in Node, no browser" icon="laptop">
    `reactor-effect-native` binds libwebrtc through Node-API: owned BGRA frames and PCM in Node and
    Bun, with no headless Chromium. On hosted H3: 1344×768 at about 24 fps, no frame lost.
  </Card>
  <Card title="Build offline, for free" icon="setting">
    `ReactorTest` is Reactor in memory: the coordinator's HTTP API and an H3 model speaking the real
    wire protocol, on the Effect clock, with timing measured on paid runs and injectable faults.
    Under `TestClock`, an hour of programme with six renewals runs in about 20 seconds.
  </Card>
  <Card title="Know what reached Reactor" icon="approve-check">
    Every failed command says whether it was never sent, answered, or unknown. An enqueue whose
    reply was lost is never sent again, so a lost reply never doubles a clip.
  </Card>
  <Card title="Sessions outlive tokens and processes" icon="random">
    Tokens bound to the session refresh before they expire, a dropped connection recovers on the
    same session, and a crashed owner's session is adopted by the next process.
  </Card>
  <Card title="Billing safety as an API" icon="warning">
    Every creating token caps its session, `close` confirms termination with an independent read,
    and `Session.mayStillBill` names what may still be running.
  </Card>
</CardGrid>
